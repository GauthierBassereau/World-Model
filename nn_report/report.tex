\section{Project Idea and Scope}

World models learn to predict how an environment changes over time. For robot manipulation, this is difficult because an image contains regions with very different levels of predictability. Static background patches are usually easy, while robot grippers, small objects, contact boundaries, and occlusions are much harder. Nevertheless, conventional diffusion and flow-matching models assign one noise level to the entire image and spend the same denoising effort everywhere.

I ask a narrow question: \emph{does training a robot world model with different noise levels across the patches of the same image improve its spatial and temporal understanding?} My motivation comes from Patch Forcing \cite{schusterbauer2026patch}, which extends Diffusion Forcing \cite{chen2024diffusionforcing} from sequence elements to image patches. Its main idea is that partially resolved regions can provide context for more difficult regions. I find this particularly relevant to video dynamics: a clear view of the table, robot arm, or part of an object may help the model reconstruct a nearby patch affected by motion or occlusion.

I build on the world-model code developed for my thesis, but I keep the course contribution separate and clearly scoped. For this project, I:
\begin{itemize}
    \item converted the BridgeData V2 experiments to a simple episode-based LeRobot evaluation setup;
    \item implemented patch-wise noise sampling while preserving the original frame-level baseline;
    \item tested two alternatives for signal conditioning;
    \item added a patch-difficulty prediction head and an adaptive sampler for later experiments; and
    \item compared frame-level and patch-level training quantitatively and through decoded video rollouts.
\end{itemize}

\section{Starting Model}

I encode each RGB frame with a frozen DINOv2-base encoder \cite{oquab2023dinov2}. The resulting state is a $16\times16$ grid of 256 patch tokens, each with 768 features. I use a 24-block spatial-temporal transformer with width 1024 and 16 attention heads to predict future DINO features. My model has approximately 400 million parameters. Spatial attention connects patches within a frame, while causal temporal attention carries information between frames. I supply robot actions through a separate action token.

I train the model with a linear flow-matching path. Given a clean latent patch $z$, Gaussian noise $\epsilon$, and signal level $s\in[0,1]$, I construct the corrupted input as
\begin{equation}
    z_s = s z + (1-s)\epsilon ,
\end{equation}
where $s=0$ is pure noise and $s=1$ is clean data. I train the network with a velocity objective. In my original setup, each frame $t$ has one sampled signal level $s_t$, shared by all 256 patches. This is already Diffusion Forcing across time because different frames in a sequence can have different signal levels, but the corruption remains uniform within each image.

\section{Patch Forcing Extension}

\subsection{Patch-level corruption}

For Patch Forcing, I first sample a frame-level base signal $b_t$ from the same configurable scheduler used by the baseline. In these experiments the base distribution is logit-normal. Each patch signal is then sampled from the lower half of a Gaussian centered on $b_t$:
\begin{equation}
    s_{t,p} \leq b_t, \qquad
    s_{t,p} \sim \mathcal{N}\!\left(b_t,\,
    \min\left(\frac{b_t}{2},\,0.6\right)^2\right)
    \text{ truncated below } b_t .
\end{equation}
Values falling below zero are resampled inside the valid interval. The base signal therefore controls the maximum amount of clean information in the frame, while the patches span a range of harder, noisier states. This follows the Logit-Normal Truncated Gaussian motivation of Schusterbauer et al.\ \cite{schusterbauer2026patch}: unconstrained independent patch timesteps can leak nearly clean context into almost every training example, whereas truncation keeps the patch distribution tied to a meaningful global state.

\subsection{Conditioning ablation}

My main design question was how to tell the transformer which noise level belongs to each patch. The source paper uses spatially varying timestep conditioning through adaptive normalization. My architecture does not use AdaLN-Zero, so I first concatenated a learned 256-dimensional signal embedding to every 768-dimensional DINO token before projecting it into the transformer. This gave the network explicit access to every $s_{t,p}$, but it also changed the visual input interface and attached a large learned code to every patch.

I did not obtain reliable training with this version. Evaluation initially improved, then began to degrade at approximately 7,000 steps and later rose sharply before I stopped the run. My current interpretation is that concatenating the learned signal embedding interfered with the structure of the pretrained DINO representation. I cannot establish this from a single run, however, and this conditioning mechanism requires further investigation.

In my final version, I remove per-patch signal conditioning entirely. I still corrupt every patch with its individual signal level, but I give the model only the original frame-level signal token containing $b_t$. The model must infer which regions are trustworthy from the noisy features and from their spatial and temporal context.

My main goal is to improve the learning signal, rather than primarily to accelerate generation by denoising easy patches before difficult ones. Across training, the same image can appear with many different spatial corruption patterns. Since I do not reveal the local signal levels, the transformer must compare neighboring regions, recover object boundaries and identities, and use clearer patches to interpret noisier ones. I expect this to encourage the model to learn stronger spatial relationships and more persistent object representations instead of solving every patch as an isolated denoising problem.

I also implemented the difficulty head and adaptive sampler proposed in the source paper. I train the head to predict one log-variance value per patch from the detached velocity error, and I use this score to let the sampler advance easy patches while refining difficult patches with smaller inner steps. This was not the main focus of my experiments: I implemented and tested the mechanism, but my primary question was whether patch-wise corruption itself provides a better training objective for a world model.

\section{Data and Experimental Setup}

I use BridgeData V2 \cite{walke2023bridgedatav2} in LeRobot format. Bridge episodes are short, typically around seven seconds, so sampling many starting indices from the same episode would produce highly overlapping examples. I therefore use one dataset index per episode, always beginning at the episode start. I extract 40 frames at 5 Hz for training, covering most or all of a typical trajectory. This also reduces the amount of terminal padding that complicated my earlier experiments.

I reserve 32 randomly selected episodes for evaluation and exclude them from training. I use the same split and evaluation procedure for every model. I report two complementary metrics:
\begin{itemize}
    \item \textbf{Teacher-forced prediction} measures one-step generation. For every valid adjacent frame pair, I give the model a clean ground-truth frame as context and ask it to generate the next frame using the corresponding action. I then compute mean squared error in DINO feature space. Since generated predictions are not fed back into the model, this metric mainly measures local denoising and next-state prediction.
    \item \textbf{Autoregressive rollout} measures error accumulation. I provide ten clean context frames, then generate the future sequence one frame at a time using the ground-truth actions. Every generated latent is fed back into the temporal context before generating the next frame. The horizon-$H$ metric averages DINO-feature MSE over the first $H$ generated frames; for example, horizon 20 summarizes the first 20 rollout steps rather than only the twentieth frame.
\end{itemize}
I also decode selected DINO rollouts to RGB for qualitative inspection, but I do not use decoded pixels as a training or evaluation loss.

\section{Experiments and Results}

\subsection{Training and held-out evaluation}

I compare three runs in Figure~\ref{fig:quantitative-results}: the frame-level baseline, the failed Patch Forcing variant with explicit per-patch conditioning, and the final Patch Forcing variant conditioned only on the frame-level base signal. The upper-left panel shows the raw training velocity loss. The final Patch Forcing run has the lowest value throughout training, but this comparison must be treated carefully because patch-wise and frame-wise corruption produce different training distributions. The held-out metrics provide the more meaningful comparison.

The upper-right panel shows teacher-forced next-frame MSE. The explicitly conditioned variant improves at first, but its evaluation error starts rising at approximately 7,000 steps and then becomes unstable. Its training loss does not show an equally clear failure, demonstrating why training loss alone is insufficient for selecting a world model.

The final Patch Forcing variant behaves very differently. Its teacher-forced error decreases quickly and remains close to 0.16 for most of training. The baseline stays near 0.20--0.23 during its best period, then begins to degrade after roughly 40,000 steps despite a continuing reduction in training loss. In contrast, the Patch Forcing evaluation curve remains stable and reaches its best values near the end of the run. One plausible explanation is that every video is observed under many spatial corruption patterns. This increases the variety of prediction problems without requiring additional trajectories and appears to reduce overfitting.

The lower panel reports autoregressive error at increasing rollout horizons. The successful Patch Forcing model is better at every horizon, and the gap grows as predictions are fed back into the model. At horizon 20, its MSE is approximately 0.23, compared with 0.32 for the baseline and 0.47 for the failed variant. At horizon 40, the corresponding values are approximately 0.24, 0.34, and 0.61. The relatively small increase from horizons 20 to 40 for the successful model indicates substantially more stable long-term generation.

\subsection{Qualitative rollout}

Figure~\ref{fig:qualitative-results} shows a decoded held-out rollout in which the robot moves a circular metal object towards a pan. The columns are successive points in the generated sequence. The top row is the ground truth, the middle row is the frame-level baseline, and the bottom row is the successful Patch Forcing model.

The baseline initially reconstructs the scene, but it does not preserve the manipulated object consistently as the motion develops. The object becomes poorly separated from the gripper and its final relation to the pan does not match the demonstrated placement. The Patch Forcing rollout retains the circular object's identity through the motion and produces a more coherent final placement. The prediction is not a perfect physical reconstruction, but the object remains present and involved in the interaction. This is representative of the main qualitative improvement I observed: fewer disappearing objects and more consistent relations between the robot, manipulated objects, and surrounding scene.

Together, these results support my hypothesis that heterogeneous patch corruption can provide a better learning signal for world modelling. Since the final model does not receive the local signal levels, it must use semantic, spatial, and temporal context to infer which regions are reliable. The failed conditioning run does not establish that explicit patch conditioning is harmful in general; it only shows that my concatenation-based implementation was unstable and that other conditioning mechanisms require further investigation.

\section{Limitations and Conclusion}

My main limitation is experimental scale. Each long run required roughly two days on six H200 GPUs, which limited me to one run per configuration and prevented systematic hyperparameter sweeps. None of the experiments was run to full convergence, so I cannot yet determine their final asymptotic performance or provide uncertainty estimates across random seeds. The available curves do, however, show that the successful Patch Forcing model converges substantially faster under the same evaluation protocol.

Within these limits, I reached the central objective of the project. I integrated patch-level corruption into an existing 400M-parameter world model, identified an unstable conditioning design, and found a simpler variant that improved both teacher-forced prediction and autoregressive rollout. The quantitative gains are consistent with the qualitative result: the model preserves objects more reliably and produces more coherent interaction dynamics and physics.

More experiments are required before drawing broader conclusions about the best patch distribution or conditioning mechanism. Nevertheless, my current results indicate that patch-level noise is a useful way to enrich the training signal. It exposes the model to more varied reconstruction problems and encourages it to learn relationships across a scene, leading to faster convergence and better generation within the compute budget available for this project.
